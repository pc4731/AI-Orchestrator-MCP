KEY IMPLEMENTATION DETAILS:

--- RESUMABLE UPLOAD (TUS Protocol) ---
Use @tus/server package. When upload completes:
1. Save metadata to media_files table (status: 'processing')
2. Push job to queue:media-processing
3. Worker: extract thumbnail, generate waveform peaks, create HLS segments
4. Update media_files record (status: 'ready')
5. Emit 'media:ready' socket event to client

--- TRANSCRIPTION FLOW ---
1. Client requests transcription for media_file_id
2. API creates transcript record (status: 'pending')
3. Push job to queue:transcription with {transcriptId, s3Key, language}
4. Worker calls Python AI service: POST /api/transcribe
5. Python runs whisper-large-v3 + pyannote diarization
6. Returns JSON: {words: [{word, start, end, speaker, confidence}]}
7. Worker saves words to transcript_words table (bulk insert)
8. Updates transcript status: 'ready'
9. Emits 'transcript:ready' socket event
10. Client fetches transcript and renders in Script Editor

--- EXPORT FLOW ---
1. Client sends export config: {compositionId, format, resolution, quality}
2. API creates export record + pushes to queue:export
3. Worker fetches composition, scenes, layers, transcript
4. Builds FFmpeg command dynamically based on layers:
   - Concatenate video clips per scene order
   - Apply ignored words (cut those segments)
   - Overlay captions if enabled (drawtext filter)
   - Apply audio filters (denoise, loudnorm)
   - Render text overlays, logos
5. Stream progress via Redis pub/sub → client
6. Upload output to S3, update export record
7. Send email notification with download link

--- SCRIPT EDITOR (Slate.js) IMPLEMENTATION ---
The transcript editor is the CORE of the app. It must:
- Render transcript words as editable rich text nodes
- Each word node stores: {text, startMs, endMs, speakerId, isFiller, isIgnored}
- Clicking a word → seek video playhead to word.startMs
- As video plays → highlight current word in real-time
- Selecting + deleting text → adds those word segments to "ignored" list
  (does NOT delete from DB, marks as ignored, FFmpeg skips them on export)
- Undo/Redo stack managed by Slate history plugin
- Decorations (Slate) for:
  → Filler words: dashed blue underline
  → Ignored/deleted text: strikethrough + gray color
  → Current playing word: yellow highlight background
  → Search matches: orange highlight
- Speaker labels: Each paragraph block has a speaker header
  → Click speaker name → edit speaker name/color
  → All paragraphs from that speaker update
- Right-click context menu:
  → Cut to timeline | Copy text | Delete | Mark as filler | Add comment
- Floating toolbar on text selection:
  → Cut | Delete | AI Fix (regenerate via voice clone) | Comment | Copy
- The editor must support 50,000+ words without performance issues
  → Use Slate's virtualization or windowing for long transcripts

--- TIMELINE COMPONENT ---
Built with canvas (konva.js or raw canvas) or react-timeline-editor:
- Multiple tracks:
  Track 0 (bottom): Script/Audio waveform (base track)
  Track 1:          Video clips track
  Track 2:          B-roll / overlay video
  Track 3+:         Custom audio tracks
  Track N:          Graphics / text overlays track
- Playhead: vertical red line, draggable, synced with video
- Scene boundaries: vertical dashed white lines, draggable to trim
- Clip handles: drag left/right edges to trim
- Zoom: mouse wheel or slider (range: 10px/sec to 500px/sec)
- Mini-map: above main timeline for navigation
- Keyboard shortcuts:
  Space     → play/pause
  J/K/L     → shuttle backward/pause/forward
  ,/.       → step frame backward/forward
  I/O       → set in/out points
  S         → split at playhead
  Delete    → delete selected
  Cmd+Z     → undo
  Cmd+Shift+Z → redo

--- REAL-TIME COLLABORATION ---
Socket events (socket.io rooms by compositionId):

Client emits:
  'cursor:move'        → {x, y} every 50ms (throttled)
  'transcript:edit'    → {operation: 'insert'|'delete', position, text}
  'scene:update'       → {sceneId, changes}
  'layer:update'       → {layerId, changes}
  'playback:seek'      → {ms} (follow-me mode)
  'presence:ping'      → heartbeat every 10s

Server emits to room (except sender):
  'cursor:update'      → {userId, name, avatar, x, y, color}
  'transcript:patch'   → {userId, operation, position, text}
  'scene:patched'      → {userId, sceneId, changes}
  'layer:patched'      → {userId, layerId, changes}
  'user:joined'        → {userId, name, avatar}
  'user:left'          → {userId}
  'job:progress'       → {jobId, type, progress, status}

Conflict resolution: Last-Write-Wins for most properties.
For transcript: Operational Transformation (OT) using ot.js or Yjs (CRDT).
STRONGLY RECOMMENDED: Use Yjs with y-socket.io for transcript collaboration.

--- TRANSCRIPTION ENDPOINT (POST /api/v1/transcribe) ---
Input: {s3_key, language, enable_diarization, num_speakers}
Process:
  1. Download audio from S3 to temp file
  2. If video: extract audio with ffmpeg
  3. Run whisper-large-v3 with word_timestamps=True
  4. If enable_diarization: run pyannote.audio pipeline
  5. Align diarization segments with whisper words
  6. Detect filler words using spaCy (um, uh, like, you know, basically, etc.)
  7. Return {words, speakers, language, duration, confidence}
Output: Full word-level transcript with speaker labels and timestamps

--- FILLER WORD DETECTION ---
Method: spaCy token matching + custom regex patterns
Filler list: um, uh, like, you know, basically, literally, actually, right?,
             so, I mean, kind of, sort of, you see, well, okay, alright
Also detect: repeated words (the the), stutters (I-I-I), long silences
Return: List of word indices that are filler

--- SILENCE DETECTION ---
Method: librosa + WebRTC VAD
1. Load audio with librosa
2. Run VAD to detect speech segments
3. Invert to get silence segments
4. Filter by min_silence_duration (default 500ms)
5. Return list of {start_ms, end_ms} silence segments
6. Client can "Remove Silences" which ignores these in editor

--- STUDIO SOUND (Audio Enhancement) ---
Method: DeepFilterNet (state-of-art speech denoiser)
1. Load audio segment
2. Run DeepFilterNet model
3. Apply loudness normalization (EBU R128 via pyloudnorm)
4. Export enhanced audio
5. Upload to S3, return new s3_key

--- AI CLIPS DETECTION ---
Method: Custom transformer + OpenAI embeddings
1. Get full transcript text + timestamps
2. Chunk into segments with sliding window
3. Compute embeddings for each chunk
4. Score each chunk on:
   - Semantic density (information per second)
   - Sentiment peaks (excitement, emotion)
   - Speaker energy (audio amplitude peaks)
   - Topic transitions (embedding distance)
5. Score segments, pick top N by score
6. For each: generate thumbnail, title, description
7. Return clips: [{start_ms, end_ms, score, suggested_title, ...}]

--- VOICE CLONE (OVERDUB) ---
Method: ElevenLabs API (recommended) or Coqui TTS
1. User uploads 30+ seconds of their voice (clean audio)
2. Send to ElevenLabs voice cloning API
3. Store voice_id in voice_clones table
To generate speech:
1. User selects word in transcript, types replacement
2. Call ElevenLabs TTS with voice_id + replacement text
3. Get audio blob, trim to fit word duration
4. Upload to S3
5. Create audio layer in timeline at word's timestamp
6. Original word marked as "overdubbed" in transcript

--- TRANSLATION ---
Method: DeepL API (best quality) or Helsinki-NLP models
Input: {transcript_words, target_language}
Process:
1. Group words into sentences
2. Send sentences to DeepL API
3. Align translated sentences back to timestamps
4. Create new caption set in target language
Supported: 20+ languages (EN, ES, FR, DE, JA, ZH, HI, PT, etc.)

--- UNDERLORD AI ASSISTANT ---
Model: GPT-4o or Claude 3.5 Sonnet via API
System prompt includes:
  - Full transcript text
  - Current composition structure
  - Available edit operations as function calls
Function tools available to the LLM:
  - remove_filler_words(threshold: float)
  - remove_silences(min_duration_ms: int)
  - generate_captions(style: string)
  - create_highlight_clip(duration_seconds: int)
  - tighten_pacing(target_wpm: int)
  - summarize_transcript()
  - find_best_moments(topic: string, count: int)
  - add_intro_card(text: string)
  - normalize_audio()
  - generate_title_and_description()
When LLM calls a function → execute it → apply changes to composition
Return: {message, operations_performed, new_composition_state}

7. MEDIA PROCESSING PIPELINE
================================================================================

--- HLS STREAMING SETUP ---
After upload, convert video to HLS:
  ffmpeg -i input.mp4 \
    -c:v libx264 -crf 22 -preset fast \
    -c:a aac -b:a 128k \
    -hls_time 6 \
    -hls_playlist_type vod \
    -hls_segment_filename 'segment_%03d.ts' \
    output.m3u8
Upload all .ts segments + .m3u8 to S3
Use CloudFront signed URLs for secure streaming

--- WAVEFORM GENERATION ---
  audiowaveform -i input.mp3 -o waveform.json \
    --pixels-per-second 100 --bits 8
Store peaks array in media_files.waveform_data (JSONB)
Client uses this to render WaveSurfer.js without re-fetching audio

--- THUMBNAIL EXTRACTION ---
  ffmpeg -i input.mp4 -ss 00:00:02 -vframes 1 -q:v 2 thumbnail.jpg
Generate at: 2s, 25%, 50%, 75% timestamps
Resize to: 320x180, 640x360, 1280x720

--- EXPORT PIPELINE (FFmpeg command builder) ---
The export worker dynamically builds an FFmpeg command:
1. Collect all "active" scenes (not deleted)
2. For each scene, collect clips in order
3. Build filter_complex for:
   - Concatenation: [0:v][1:v][2:v]concat=n=3:v=1:a=0[outv]
   - Caption overlay: drawtext=text='...':fontsize=36:y=h-th-50
   - Logo overlay: [outv][logo]overlay=10:10[final]
   - Audio mixing: amix=inputs=2:duration=first
4. Apply ignored word segments as trim cuts
5. Run FFmpeg with progress callback
6. Stream progress percentage to Redis pub/sub
7. Upload output file to S3 with signed URL (7-day expiry)

8. AUTHENTICATION & AUTHORIZATION
================================================================================

--- AUTH FLOW ---
1. Register: email + password → hash with bcrypt (rounds: 12) → save user
2. Login: verify password → generate:
   - Access Token: JWT, expires 15 minutes, contains {userId, workspaceId, plan}
   - Refresh Token: opaque random string (64 chars), expires 30 days
   - Store refresh token hash in Redis: sessions:{userId} = token_hash
3. Token Refresh: POST /api/v1/auth/refresh
   - Verify refresh token exists in Redis
   - Issue new access + refresh token pair
   - Rotate refresh token (delete old, store new)
4. Logout: DELETE refresh token from Redis
5. OAuth (Google):
   - Redirect to Google OAuth URL
   - Callback: create/find user by email
   - Issue same JWT pair

--- AUTHORIZATION LEVELS ---
Public:              Share link viewers (read-only, no auth required)
Free User:           Own workspace only, limited features

Team Admin:          Manage workspace members, billing
Team Owner:          Full control, delete workspace

  - user.plan from JWT claim
